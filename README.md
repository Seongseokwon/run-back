# RaceBack (가칭)

대회 날짜를 기준으로 **역산해서** 주차별 훈련 플랜을 만들어 주는 모바일 우선 웹서비스.

> "11월 15일 하프까지 남은 10주, 목표 1:55 기준 플랜"

제품 정의·범위·근거는 [`prd-raceback-mvp_1.md`](./prd-raceback-mvp_1.md) (PRD v1.1) 참조.

## 구조

```
packages/engine/     플랜 생성 엔진. 순수 함수, 런타임 의존성 0
apps/                (예정) Next.js 웹앱
docs/adr/            설계 결정 기록
```

엔진을 분리한 이유는 PRD §11.2 — 빌드 타임에 같은 함수를 호출해 정적 SEO 페이지를
대량 생성해야 하고, 브라우저 없이 수천 케이스를 검증해야 하기 때문이다.

## 개발

Node **22.18 이상**이 필요하다. 엔진은 Node 내장 타입 스트리핑으로 `.ts` 를 그대로 실행하므로
**설치할 의존성이 없다.**

```bash
npm test                # 엔진 테스트 (node:test) — 99건
npm run table           # VDOT 구간별 예상 기록·페이스표 (눈 검증용)
npm run gain            # 향상률 모델을 PRD 초기값과 나란히 출력
npm run plan            # 플랜 한 건 생성해서 출력 (도그푸딩 케이스)
npm run typecheck       # tsc·@types/node 필요 (`pnpm install` 후)
```

## 진행 상황

| 주차 | 범위 | 상태 |
|---|---|---|
| W1 | VDOT 코어, Riegel 환산, 페이스표 | ✅ 완료 — [ADR-0001](./docs/adr/0001-vdot-model.md) 로 O3 해소 |
| W2 | 타당성 판정, 페이즈 배분, ACWR 볼륨 곡선, 세션 배치 | ✅ 완료 — [ADR-0002](./docs/adr/0002-vdot-gain-rate.md) 로 O2 해소. §11.3 불변식 전 항목 통과 |
| W3 | 대회 데이터 50개 + 입력 스텝 UI | 다음 |
| W4~ | 판정 화면, 결과 뷰, SEO, 인증 | |

`generatePlan(input)` 하나로 PlanInput → Plan 이 완성된다. 엔진은 이제 기능적으로 완결이며,
남은 것은 데이터와 UI다.

## 엔진 원칙

1. **결정론** — 같은 입력이면 항상 같은 플랜. 정적 페이지 생성이 이 성질에 의존한다.
2. **정직성** — 예측은 단일 숫자가 아니라 범위로 반환한다 (PRD §7.2).
3. **안전이 먼저** — 존별 주간 거리 상한과 ACWR 클램프는 하드 제약이며 테스트로 강제한다 (PRD §7.10, §11.3).
4. **조용히 줄이지 않는다** — 안전 규칙이 발동해 플랜이 약해지면 `notices` 로 사용자에게 알린다.

### §11.3 불변식

`test/_invariants.ts` 가 PRD §11.3 항목을 그대로 검사한다. 거리 4종 × 훈련일수 4종 ×
주차 1~52 전수 스윕과 무작위 2,000건에 적용된다. **여기 통과하지 못하면 배포하지 않는다.**
